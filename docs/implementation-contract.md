# CPZeroJS implementation contract (v0.1)

Workspace: npm workspaces, TypeScript SDK package `@cpzero/core`, CLI package `@cpzero/cli` (binary `cpzero`). Native host: C/C++, LVGL 9, QuickJS, SDL desktop + Linux framebuffer backend. App source: src/main.ts bundled IIFE, no Node/browser runtime dependency. Default demo: examples/dashboard/src/main.ts.

## Native bridge

Global `__cp` has `create(kind: string, parent: number, props: object): number`, `update(id: number, props: object): void`, `remove(id: number): void`, `log(message: string): void`, `invoke(service: string, method: string, jsonArgs: string): string` (JSON result or throws), and `stats(): object`. ID 0 means screen parent; native IDs monotonic, live table indexed by ID. Kinds: screen, column, row, label, button, input, bar, box. Props: text, width, height (number pixels or "100%"), grow, gap, padding, bg, color (hex string), fontSize (supported sizes snapped), value (string/number), min, max, hidden, disabled. Label text is set on label; button text on internal label. Native layout uses LVGL flex row/column. Screen fixed 320x170. Omitted sizes use content where appropriate. Widgets emit via global `__cpDispatch(id,event,value)`; events press/change; input value string. Global `__cpTick(nowMs)` drives SDK timers (elapsed monotonic milliseconds since app load). Native calls callbacks and drains Promise jobs with execution deadline. Host must surface JS errors, not silently continue success.

CLI: `cpzero dev [entry]` builds via esbuild, launches native/build/cpzero-host with bundle, watches/rebuilds atomically; native `--watch` polls bundle changes and reconstructs entire JS context/UI (state reset is intentional). `cpzero build [entry]` creates dist/app.js and manifest. `cpzero init <directory>` creates standalone app scaffold. `cpzero doctor` checks dependencies. Native executable args: `<bundle.js> [--watch] [--scale N] [--headless] [--frames N] [--screenshot path.ppm] [--keys Enter,Tab,...]`. Headless screenshot must allow real native rendering tests. Default simulator scale 3, logical pixels always 320x170. Native build command via scripts/build-native.sh. CMake fetches pinned dependencies. Device builds use CPZERO_BACKEND=FBDEV; require Linux ARM64 OS ABI and verification, don't claim tested on hardware.

SDK API: `createApp({title?,setup(root)})`, `ui.column(parent, props)`, row/label/button/input/bar/box; returned Widget has id, update(props), dispose(), on(event,callback). Props onPress/onChange are handled SDK-side. `signal(initial)` returns value getter/setter, subscribe; `bind(widget, property, signal)` cleanup owned by widget. `services.register(name, implementation)`, `services.call(name,method,...args): Promise<unknown>` with local JS adapters preferred then native invoke fallback. Built-in storage get/set via native service name storage methods get/set with JSON args arrays. `every(ms,fn)` and `after(ms,fn)` via __cpTick, return cleanup. `onCleanup` app lifecycle. `app.dispose()` cleans its widget tree, timers, and registered cleanup hooks. No JSX in v0.1; honest roadmap. Optional plugins can extend via services and composition; custom native widgets require C code.

Native storage lives under CPZERO_DATA_DIR or ~/.local/share/cpzero/<bundle-derived-safe-name>; keys validated; bounded values; no general shell bridge. Permissions are not a security sandbox. Single active app process. JS memory cap 16 MiB default; native LVGL memory tracked separately; total RSS unpromised. Node only build/development side.

## Extension and storage details

`ui.pagedList` keeps only one page of native row widgets. Native services register with `cpzero::registerService` in `native/services.hpp`, compiled via `CPZERO_EXTENSION_SOURCES`. Service calls exchange JSON arrays/results and execute synchronously on the UI thread; adapters must be bounded and nonblocking. A Promise-returning TS wrapper does not make native work asynchronous. `storage.get` returns null for missing keys or stored JSON null; `storage.set` resolves undefined. Dev CLI sets per-project `.cpzero/data` unless `CPZERO_DATA_DIR` is supplied.
